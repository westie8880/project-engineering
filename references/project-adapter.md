# 检索与 Skill 协作契约

## 先确定范围

遵循宿主指令层级。读取适用 AGENTS，不为了省上下文跳过强制规则。根目录未必是仓库；先从明确目录、根索引、浅层子目录定位实际仓库。首次找不到手册只做一次有边界的发现，排除依赖、构建产物、备份、vendor、临时发布副本和无关项目。不能用递归列出全部文件加截取前 N 条代替覆盖盘点。

已有手册优先复用，不强制迁目录。新生成采用 handbook-maintenance.md 中的单一结构，既有 YAML 等结构可做轻量适配，不能维护两套相互漂移的事实源。大型 AGENTS 或变更日志不是索引：读取其长期规则后，按稳定 ID/关键词检索匹配的历史决定。

手册必须写在项目已有文档根下。优先使用项目根的 `docs/project-handbook/`，如果项目已有共享文档根则沿用并在 README 标出解析后的路径。生成、更新、迁移默认只改本地工作树，不自动提交或发布。部署所需凭据使用项目外的用户批准私密清单，手册只记录清单路径和字段名，不复制凭据值。

## 分层读取

1. 启动只读手册 README（建议约600字内）、任务相关的 index.json 记录和项目适配信息，不默认读取全部模块正文、历史清单或测试日志。
2. 精确 ID 或名称/别名检索，读取命中的业务/技术条目及必要的一跳 related。建议一次最多10条元数据、约3份正文；不足时按证据扩展，不按数量强行停止完整任务。
3. 当前条目应给出对应仓库、源文件、符号和验证版本，按锚点核对任务相关代码。无命中先查同义词、模块索引，再限定源码目录查证。
4. 只有回归、历史订单、迁移、版本差异、用户问旧逻辑等任务才读 history/index.json；按同一功能 ID 与时间选快照，不遍历历史正文。普通当前状态问题不会因有历史指针而自动读历史。
5. 同一任务保存已读路径、覆盖范围和发现的冲突；上下文压缩或换对话后先复用简短任务检查点。临时检查点不写成永久业务规则。

可选助手（标准库 Python，无联网）：
`python <skill>/scripts/handbook.py lookup <handbook-root> <ID或关键词>`
返回最多10条当前元数据及 `truncated`/`remaining`；精确ID优先，并附一跳 related。历史问题显式加 `--history`。`check` 检查结构，不能证明业务事实正确。没有 Python 时按同一契约手动检索，不以此阻断任务。缺少手册只是覆盖缺口，不是扩大扫描范围或读取所有历史正文的理由。

## 版本与证据

手册是导航和已验证知识，不保证永远新鲜。记录仓库 revision、dirty 状态、源文件/符号及必要的内容哈希。启动对比目标仓库 HEAD 与变更路径：仅对受影响条目复核；无法对比时标记需核对。分支名不等于部署版本，开发代码不等于线上行为。不同环境可同时有不同事实，不简单用“最新”覆盖所有环境。

区分三个维度：
- 意图：用户批准的目标规则或契约；尚未实现也可以是有效需求。
- 实现：在某提交/工作区实读的代码、配置。
- 部署与验证：哪一环境运行什么产物，何时通过什么检查。
不能把用户期望当作已运行事实，也不能因实现不符就改写需求。发生冲突在当前条目的差异/待办段记录各自证据；只对会影响本次动作且无法裁定的点向用户询问。

## 与其它 Skill 兼容

先看已安装目录；需要发现能力时委托可用的 find-skills，遵循它的发现流程，不复制市场检索/安装机制。已有能力满足任务时不反复搜市场；没有 find-skills 也能用宿主工具目录。技能名仅是发现线索，不是强依赖。

明确分工：本 Skill 管任务范围、项目约束、覆盖台账和知识归档；框架 Skill 管实现细节；测试工具 Skill 管浏览器或测试框架操作；设计 Skill 管已授权的设计；文档 Skill 管用户要求的 Word/PDF 等成品。

没有“本 Skill 永远高于其它 Skill”的规则。遵循宿主指令层级和用户选择；兼容的约束合用，冲突时优先保留明确任务范围和仓库约定，不为了套模板迁框架或改变原型。必要的工具限制仍遵守；不扩充测试或部署授权。

跨工具迁移不假设 `$skill`、Codex MCP 或任何专用命令存在。复制 Skill 文件夹和手册后，读取 SKILL.md 即可启动；有 AGENTS/工具专用入口时只加短链接，不复制所有正文，不自动改其它 Skill 或托管插件缓存。
