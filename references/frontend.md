# 前端跨技术栈规则

## UI 与交互

- 先核对现有原型、页面入口、字段状态、动作与跳转，再实现；沿用项目设计系统和组件约定。
- 让内容层级、反馈、空态、加载态、错误态和成功态清楚可见。表单保留用户输入，危险或不可逆动作要求明确确认。
- 响应式布局、键盘操作、焦点顺序、触摸目标和对比度应满足目标平台的可访问性要求；文本、图标和颜色不单独承担语义。

## 状态与数据

- 区分本地展示状态、表单草稿、缓存数据和服务端事实；服务端事实不可由演示数据或旧缓存冒充。
- 明确加载、空结果、部分失败、重试、取消和过期状态。重复提交、刷新和返回页面不得造成重复写入。
- 权限、人员/租户范围和资源归属由服务端校验；前端只负责展示可用动作，不以隐藏按钮代替授权。

## 契约与分层

- 按公开契约调用接口，统一处理版本、分页、校验错误、业务拒绝和网络失败；字段映射集中维护，避免散落字符串。
- 页面负责编排，组件负责呈现，领域/数据层负责业务转换与请求；不要在视图中复制业务规则或直接操作不属于本层的数据源。
- 破坏性契约变更须同步类型、示例、文档和兼容策略；不把后端密钥、内部地址或敏感原始数据放入客户端。

## 测试与交付

- 覆盖代表性完整流程及平台差异，至少验证成功、空态、权限拒绝、重复操作、网络失败和恢复路径。
- 运行格式/静态检查、类型检查、构建和必要的浏览器或设备验证；记录实际验证范围与未覆盖项。
- 交付前更新本地可运行产物并确认入口生效。部署、发布和推送必须遵循用户授权与项目流程。
