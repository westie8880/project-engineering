# 后端跨技术栈规则

## 契约与分层

- 先确认业务能力、调用方、数据归属和现有不变量，再决定模块边界；按职责分层，避免控制器承载业务规则或跨模块直接写表。
- 对外契约明确请求、响应、状态、错误、幂等、分页和版本兼容；契约变更同步更新文档、示例和客户端适配。
- 领域规则集中在可测试的业务服务/用例中，持久化与外部适配通过清晰接口隔离；跨模块通过公开 API 协作。

## 数据、错误与并发

- 涉及状态、名额、额度或库存的操作使用一致的事务和并发控制；重复请求、重试和回调必须幂等，不能重复扣减或重复发放。
- 区分参数错误、权限拒绝、业务不可用、外部失败和系统故障，返回稳定可识别的错误并记录关联标识；不得吞掉异常或伪造成功。
- 保留必要历史事实、审计和快照；迁移采用可回滚或可验证的增量方式，不清理未经确认的既有数据。

## 配置与安全

- 配置按环境注入并校验必需项；密钥、令牌和个人敏感数据不得进入源码、日志、示例或测试快照。
- 每次请求校验身份、权限、租户/项目范围、资源归属和输入边界；默认拒绝越权访问，日志按最小必要原则脱敏。
- 外部系统调用设置超时、重试边界和失败降级；外部事实不确定时保持明确的待处理或失败状态。

## 测试与交付

- 测试覆盖核心业务链、不变量、事务边界、幂等、并发冲突、权限拒绝、外部失败和迁移；测试数据不得依赖不可控线上事实。
- 运行单元、集成/契约、静态检查、构建及必要的真实联调；区分模拟结果与真实系统验证并记录证据。
- 更新本地运行产物并确认配置和路由生效后再交付。部署、推送、数据变更和回滚遵循项目流程及用户授权。
